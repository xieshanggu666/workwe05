# 家庭营养膳食规划系统

基于《中国居民膳食营养素参考摄入量》与多维约束求解的家庭每日 / 每周配餐工具。输入家庭成员画像、预算与忌口，输出满足热量、宏量营养素供能比、微量营养素达标、预算上限、过敏原规避与食材轮换要求的完整膳食方案。

## 快速开始

```bash
npm install
npm run dev
```

启动后自动选择空闲端口并打开浏览器。仅依赖 Node.js 原生模块，无需任何第三方包，macOS / Windows / Linux 均可运行。

## 功能特性

- **膳食参考摄入量（RNI）计算**：按年龄分层、性别、活动水平（轻 / 中 / 重体力）与膳食目标（维持 / 减重 / 增肌）动态计算每日能量与 9 类营养素需求，钠按上限约束。
- **单日多维约束求解**：在固定三餐模板（早：主食+蛋奶+水果；午 / 晚：主食+蛋白主菜+两蔬+油脂；加餐坚果）基础上，迭代调整克重与食材，同时满足：
  - 热量落在目标 ±5% 区间
  - 宏量营养素供能比：脂肪 20-30%、蛋白质 10-20%、碳水 50-65%
  - 微量营养素达标度与钠上限
  - 每日预算上限（超限时优先在同类食材内替换更廉价选项，其次压缩克重）
  - 过敏原规避与指定食材排除
- **周菜单生成**：7 天 × 三餐整体编排，保证：
  - 午餐蛋白质来源类别（禽肉 / 猪肉 / 牛肉 / 羊肉 / 鱼类 / 虾贝 / 豆制品）逐日轮换且相邻天不重复
  - 相邻两天不出现重复食材
  - 肝脏类食材全周至多 1 次
  - 全周蛋白质来源类别不少于 5 类
- **家庭采购与库存管理**：
  - 家庭成员档案与过敏原登记，采购 / 配餐自动规避**全家过敏原并集**（含双重拦截）
  - 按周菜单聚合净需求（需求 − 在库 − 待买，加 10% 安全余量并按 10g 取整），生成采购清单并按成员待买金额负载**自动分工**，可改派
  - 确认到货（可登记实际克重与实际单价）后入库存、记实际支出；手动添加采购项
  - 按配餐逐日确认消耗或手动消耗，自动扣减库存（不足或缺料给出明细），并累计**本周限次用量**
  - 库存变化同步：**预算**（已采购 / 待买占用 / 预计总支出 / 余额 / 超支 / 价格偏差 / 库存估值）、**过敏规避**（在库 / 待买致敏食材预警）、**后续配餐**（在库食材优先、库存内零边际采购成本、净采购预算约束、库存与限次逐日结转）
  - 采购周切换：未到货任务与库存结转、限次计数清零；周菜单按周期绑定版本，旧周菜单与消耗记录保留可追溯但不可重复入账；状态持久化于 `data/household.json`
- **家庭分餐协作（三阶段确认流水线）**：
  - 成员可兼任**家长**（`parent`）与**采购负责人**（`buyer`）角色（至少各一名）；普通成员确认自己的替换
  - 一次生成按**每位成员营养目标**（RNI 热量占比）分摊克重的一周菜单，逐人给出热量与 9 项营养素达标度
  - **阶段一 · 家长确认份量**：可为任一成员微调每道菜克重（留痕），逐人确认；未完成不能进入下一阶段
  - **阶段二 · 成员确认替换**：每道菜每位成员独立「接受」或「同类替换」（库存优先候选、净采购成本可见）；替换受全家过敏原并集 + 个人过敏原、排除清单、周限次、同品类（蛋白菜限高蛋白）多重约束；家长可代确认
  - **阶段三 · 采购负责人确认到货**：登记实际克重 / 单价后入库记账；非采购负责人、阶段未到均被拒绝
  - **全程同步**：份量与替换即时重建净采购清单（库存 / 待买抵扣、重建幂等、负责人沿用），预算占用 / 实际支出 / 超支实时更新；按天消耗按「成员 × 菜品」逐条扣库存（缺料整体回滚）并携带 `member` 与 `meal_ref` 可追溯
  - 审计时间线（生成 / 份量 / 替换 / 到货 / 消耗）与成员消耗台账；菜单与采购周绑定，旧周菜单保留可追溯但不可再入账
- **营养可视化**：单日三餐卡片、热量达成度、宏量供能比条、微量营养素达标度网格、周多样性统计；分餐协作的三阶段进度条、成员营养卡、逐人份量表（可在线调整 / 替换 / 到货）、成员消耗台账与审计记录；采购库存看板（预算卡片 / 成员卡片 / 采购表 / 逐日消耗 / 库存表 / 预警）。

## 目录结构

```
nutrition_planner/
├── engine/
│   ├── foods.js          # 食材营养数据库（64 种食材 × 12 项营养素 + 价格 + 可食部 + 过敏原 + 周限次）
│   ├── requirements.js   # 膳食参考摄入量计算（画像分层 + 活动 / 目标系数）
│   ├── constraints.js    # 单日多维约束求解引擎（克重调整、食材替换、库存优先与净采购预算）
│   ├── menu.js           # 周菜单生成器（类别轮换 + 相邻天不重复 + 周限次 + 库存逐日结转）
│   ├── household.js      # 家庭采购与库存（成员角色 / 过敏原并集 / 清单分工 / 到货 / 消耗 / 预算 / 预警）
│   └── mealplan.js       # 家庭分餐协作（按成员营养目标分餐 + 份量/替换/到货三阶段流水线 + 追溯）
├── web/
│   └── index.html        # 单页前端（单日配餐 / 周菜单 / 分餐协作 / 采购与库存四视图）
├── tests/
│   ├── run_tests.js          # 34 项配餐引擎自动化测试
│   ├── run_household_tests.js # 33 项采购库存与库存联动配餐测试
│   └── run_mealplan_tests.js  # 22 项家庭分餐协作测试
├── data/                 # 家庭状态持久化（自动生成，已在 .gitignore）
├── server.js             # HTTP 服务与 REST API
├── start.js              # 一键启动（自动选端口 + 打开浏览器）
└── package.json
```

## API

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/system` | GET | 服务信息 |
| `/api/meta` | GET | 画像选项、过敏原集合、营养素标签等元数据 |
| `/api/foods` | GET | 食材数据库（含分类、价格、过敏原、周限次） |
| `/api/plan` | POST | 单日膳食方案求解（可选 `stock` 库存联动） |
| `/api/week` | POST | 周菜单生成（可选 `stock` / `weekly_used`） |
| `/api/household` | GET | 家庭采购库存总览（预算 / 成员 / 采购 / 库存 / 预警 / 配餐同步输入） |
| `/api/household/budget` | POST | 设置本周采购预算 |
| `/api/household/members` | POST | 添加家庭成员（含过敏原与协作角色 `roles: ["parent"|"buyer"]`） |
| `/api/household/members/:id` | PUT / DELETE | 编辑 / 删除成员（删除后其任务改未分配；至少保留一名家长与采购负责人） |
| `/api/household/shopping/build` | POST | 按周菜单生成 / 刷新分工采购清单（自动并入全家过敏原与库存抵扣） |
| `/api/household/shopping` | POST | 手动添加采购项（过敏食材拦截） |
| `/api/household/shopping/:id/assign` | POST | 改派采购负责人 |
| `/api/household/shopping/:id/arrive` | POST | 确认到货（实际克重 / 实际单价，入库存并记账） |
| `/api/household/shopping/:id` | DELETE | 删除采购任务 |
| `/api/household/consume/day/:d` | POST | 按第 d 天配餐确认消耗（校验缺料、扣库存、累计限次；菜单须属于当前采购周，旧周菜单返回 `STALE_WEEK`） |
| `/api/household/consume` | POST | 手动消耗指定克重（不可超扣） |
| `/api/household/stock` | POST | 期初 / 盘库录入（填 0 清除） |
| `/api/household/cycle` | POST | 开启新采购周（待买与库存结转、限次清零） |
| `/api/household/meal/build` | POST | 按成员营养目标生成分餐菜单并同步采购净需求（三阶段流水线初始为份量确认） |
| `/api/household/meal/portions` | POST | 家长确认份量（`actor` 须为 parent；可带 `member_id` 与 `adjustments:[{dish_id,member_id?,grams}]`） |
| `/api/household/meal/dishes/:id/candidates` | POST | 查询某成员在该菜品上的同类替换候选（库存优先、过敏 / 限次过滤、含净采购成本） |
| `/api/household/meal/substitutions` | POST | 成员确认接受或替换（`actor` 为本人或家长；全家/个人过敏原、跨类、周限次拦截） |
| `/api/household/meal/shopping/:id/arrive` | POST | 采购负责人在到货阶段确认到货（`actor` 须为 buyer，可登记实际克重 / 单价） |
| `/api/household/meal/consume/day/:d` | POST | 按成员×菜品一次性消耗（缺料整体回滚，日志含 `member` 与 `meal_ref`；旧周返回 `STALE_WEEK`） |

`/api/plan`、`/api/week` 在原有参数外支持 `stock: {食材id: 在库毛重克}`：在库食材优先入选、库存覆盖部分零边际采购成本，
响应增加 `purchase_cost`（库存抵扣后的净采购额，预算按此口径约束）、`stock_used` 与消耗后的 `stock_remaining`；
周菜单响应另含 `weekly_purchase_cost` 与逐日结转的余量。

`/api/plan` 请求示例：

```json
{
  "profile": { "age_group": "adult_m", "activity": "moderate", "goal": "maintain" },
  "budget": 25,
  "allergens": ["乳"],
  "exclude": ["broccoli"]
}
```

响应包含 `feasible`（是否满足全部约束）、`items`（每餐每项食材的克重与费用）、`totals`（营养素汇总）、`ratios`（三大供能比）、`adequacy`（各营养素达标度）与 `requirement`（该画像的摄入参考值）。

## 测试

```bash
npm test            # 配餐引擎 34 项
npm run test:household  # 采购库存 33 项
npm run test:meal   # 分餐协作 22 项
npm run test:all    # 全部 89 项
```

测试覆盖食材数据库完整性、能量守恒、参考摄入量分层、单日约束求解、过敏原 / 排除项过滤、周限次、周菜单轮换与确定性，
以及家庭成员 / 角色守卫 / 过敏原并集、净需求聚合与安全余量取整、负载分工、库存与待买抵扣（含重建幂等）、到货实际价、消耗与缺料拦截、
预算同步与超支、库存优先配餐、净采购预算约束、周菜单库存逐日结转、周期切换与三类预警（过敏 / 超支 / 缺料）；
分餐协作另覆盖按成员 RNI 热量分摊与达标度、三阶段阶段锁与角色权限、份量微调留痕、替换候选与过敏 / 跨类 / 限次拦截、
替换后采购与预算同步、按成员入账的消耗与可追溯 `meal_ref`、成员消耗台账及旧周菜单失效。
